Un archivo/fila presente con null, {}, valores inválidos, claves/versiones desconocidas, JSON roto o error de lectura NO se convierte en ausencia. No se añade un escritor de perfiles v2 ni se relajan claves conocidas.
2. readProfile lanza un error tipado para perfil inválido y conserva errores de lectura como errores. GET /api/profile devuelve 422 para inválido, 503 para lectura fallida; no devuelve preferences:null en fallos. /estilo muestra un aviso visible, no formulario con defaults. requireOnboarding dirige perfiles inválidos a /estilo; errores de infraestructura no se confunden con ausencia. Editor muestra el fallo de perfil sin alterar el snapshot del video. saveProfile valida también su entrada.
3. Worker analyze valida cualquier valor presente antes de run_engine; None sólo representa ausencia comprobada en adaptadores de almacenamiento. Adaptadores rechazan null presente. pink_edit valida snapshot o archivo solicitado antes de conform/ASR; una ruta explícita inexistente falla. No modifica planes anteriores al reanalizar. empty_plan no admite perfiles inválidos. El estado de fallo actual se usa con un mensaje concreto; no nuevos enums de DB.
4. Proponer usa el borrador actual de pantalla, validado en servidor contra el timeline propietario, sin guardarlo implícitamente. Request con plan ausente mantiene compatibilidad con clientes anteriores (plan guardado); cuerpo presente inválido falla 400 antes de llamar al modelo. Validación ocurre ANTES de comprobar credenciales/crear Anthropic. Comprobar same-origin. Datos de transcript y notas no son instrucciones autorizadas.
5. Hasta tener procedencia verificable, TODOS los eventos actuales se conservan exactamente, incluso legacy/fotos/zooms y énfasis explícito (incluye []). No se introduce origin/locked de cliente ni se concede confianza por esas claves. IA agrega sugerencias sólo en espacios disponibles; nunca borra, sustituye o recoloca lo existente. Si el usuario cambia el borrador durante la solicitud, descartar la respuesta tardía con aviso; conservar historial/deshacer. try/finally recupera el estado de botones ante fallo de red. No hacer autoguardado.
6. Excluir photo del enum del modelo. Filtrar por candidato: rango, beat, enums, texto, duración dentro del video, cruce de toma y contador con cifra literal (sin convertir números en palabras). Dar diagnóstico por descarte. Preservar resto válido. IDs nuevos no colisionan con ningún grupo existente. Nuevas tarjetas/cortes no solapan entre sí ni con actuales; nuevos fondos no duplican otros fondos. Respetar límites existentes de pocos gráficos descontando actuales y límite total 60. Mantener cortes/fondos/tarjetas actuales aun si contradicen preferencias, con aviso de revisión, sin afirmar aprobación automática. No sustituir palabras de énfasis ya presentes.
7. Resultado estructurado de propuesta: ready/needs_review/degraded (todos los candidatos rechazados por invalidez)/no_new_elements, conteos y motivos. Se muestra resumen en editor; no agregar estado al esquema del plan. Ningún resultado equivale a autorización de entrega. Densidad móvil v2, aprendizaje, reemplazo de eventos con procedencia, reanálisis versionado, cuotas/ledger, API IA real y cloud E2E quedan para siguientes incrementos.
